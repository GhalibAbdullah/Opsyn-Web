The backend is a Fastify server written in TypeScript. It handles REST API requests, WebSocket connections, authentication, and job queue processing.

## Entry Point

The server is bootstrapped in `packages/server/api/src/app/app.ts`, which:
1. Sets up Fastify with Swagger documentation
2. Registers all route modules
3. Configures Socket.IO for WebSockets
4. Sets up security middleware chain
5. Initializes database connections and migrations
6. Starts job queue workers

## API Structure

### Route Modules

Each feature is a Fastify plugin registered at a specific prefix:

```typescript
// Example module registration
app.register(flowModule, { prefix: '/v1' })
app.register(tablesModule, { prefix: '/v1' })
app.register(todoModule, { prefix: '/v1' })
```

### Controller Pattern

Controllers define endpoints with TypeBox schema validation:

```typescript
export const flowController: FastifyPluginAsyncTypebox = async (app) => {
  app.post('/', {
    config: {
      allowedPrincipals: [PrincipalType.USER],
      permission: Permission.WRITE_FLOW,
    },
    schema: {
      tags: ['flows'],
      body: CreateFlowRequest,
      response: { 201: PopulatedFlow },
    },
  }, async (request, reply) => {
    const flow = await flowService(request.log).create({...});
    return reply.status(201).send(flow);
  });
};
```

### Service Pattern

Services contain business logic and are injected with a logger:

```typescript
export const flowService = (log: FastifyBaseLogger) => ({
  async create(params: CreateFlowParams): Promise<PopulatedFlow> {
    // Business logic here
  },
  async getById(id: string): Promise<PopulatedFlow> {
    // ...
  },
});
```

## Security Chain

Every request passes through the security handler chain:

```
Request → Rate Limiter → JWT Extraction → Token Verification
    → Principal Building → Permission Check → Entity Ownership → Handler
```

### Key Security Files

| File | Purpose |
|------|---------|
| `core/security/security-handler-chain.ts` | Main middleware pipeline |
| `authentication/authentication.controller.ts` | Auth endpoints |
| `authentication/authorization.ts` | Entity ownership checks |
| `authentication/permission-helpers.ts` | Permission utilities |
| `ee/authentication/project-role/rbac-middleware.ts` | RBAC enforcement |

### Flow Operations

Flows use an **operation-based** update model. Instead of directly mutating fields, changes are applied as typed operations:

```typescript
// Apply an operation to a flow
POST /v1/flows/:id
Body: {
  type: "ADD_ACTION",
  request: { parentStep: "trigger", action: {...} }
}
```

This enables real-time collaboration (operations are broadcast to other editors).

## Database Access

### TypeORM Entities

Each entity maps to a database table:

```typescript
@Entity({ name: 'project' })
export class ProjectEntity {
  @PrimaryGeneratedColumn('uuid')
  id: string;

  @Column()
  displayName: string;

  @Column()
  platformId: string;

  @Column()
  ownerId: string;
}
```

### Migrations

Database schema changes use TypeORM migrations:
- Located at `packages/server/api/src/app/database/migration/`
- 416+ migration files
- Run automatically on server start

## WebSocket Service

The WebSocket service (`core/websockets.service.ts`) handles:

1. **Authentication** — JWT verification on connection
2. **Room Management** — Join/leave project and flow rooms
3. **Active Editor Tracking** — In-memory maps for presence
4. **Event Broadcasting** — Emit events to rooms

See [WebSocket Events](/architecture/websockets) for the complete event reference.

## Workers & Job Queues

Background processing uses BullMQ with Redis:

| Queue | Purpose |
|-------|---------|
| **Flow Engine** | Execute flow steps |
| **Webhook** | Process incoming webhooks |
| **System Jobs** | Scheduled maintenance tasks |

Workers run in a separate process (`packages/server/worker/`) for scalability.
