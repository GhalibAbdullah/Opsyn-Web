OpSyn uses **PostgreSQL** as the primary data store and **Redis** for caching, job queues, distributed locks, and real-time pub/sub.

## Tech Stack

| Technology | Purpose |
|-----------|---------|
| **PostgreSQL** | Primary relational database (production) |
| **SQLite** | Lightweight alternative (development/testing) |
| **TypeORM** | Object-Relational Mapper with EntitySchema pattern |
| **Redis** | Caching, job queues (BullMQ), distributed locks, Socket.IO adapter |

## Database Connection

The database type is determined by the `AP_DB_TYPE` environment variable:

```typescript
// database-connection.ts
const databaseType = system.get(AppSystemProp.DB_TYPE)

export const databaseConnection = () => {
    return databaseType === DatabaseType.SQLITE3
        ? createSqlLiteDataSource()
        : createPostgresDataSource()
}
```

| Variable | Options | Default |
|----------|---------|---------|
| `AP_DB_TYPE` | `POSTGRES`, `SQLITE3` | `POSTGRES` |
| `AP_POSTGRES_DATABASE` | Database name | `activepieces` |
| `AP_POSTGRES_HOST` | Host | `localhost` |
| `AP_POSTGRES_PORT` | Port | `5432` |
| `AP_POSTGRES_USERNAME` | Username | — |
| `AP_POSTGRES_PASSWORD` | Password | — |
| `AP_POSTGRES_USE_SSL` | Enable SSL | `false` |

## Migrations

TypeORM migrations manage all schema changes:

- **Location**: `packages/server/api/src/app/database/migration/`
  - `postgres/` — PostgreSQL migrations
  - `sqlite3/` — SQLite migrations
  - `common/` — Shared migrations
- **Count**: 416+ migration files
- **Execution**: Run automatically on server startup
- **Naming**: Timestamped (e.g., `1734537372703-AddFlowComments`)

### Creating a New Migration

```bash
nx db-migration server-api --name=AddNewFeature
```

This generates a migration file with `up()` and `down()` methods.

## Redis — Usage Breakdown

Redis serves multiple roles in OpSyn:

### 1. Job Queues (BullMQ)

| Queue | Purpose |
|-------|---------|
| `flow-engine` | Execute flow steps |
| `webhook` | Process incoming webhooks |
| `system-jobs` | Scheduled maintenance (cleanup, alerts) |

Workers (`packages/server/worker/`) consume from these queues in separate processes.

### 2. Distributed Locks

```typescript
// Prevents concurrent execution of critical sections
const lock = await distributedLock(log).acquire('lock-key', timeout)
try {
    // critical section
} finally {
    await lock.release()
}
```

Used for:
- Flow publishing (prevent concurrent publishes)
- Trigger registration/deregistration
- Migration execution

### 3. Socket.IO Adapter

```typescript
import { createAdapter } from '@socket.io/redis-adapter'
const adapter = createAdapter(pub, sub)
```

Enables WebSocket room broadcasts across multiple server instances for horizontal scaling.

### 4. Distributed Store

Key-value cache for cross-instance data sharing (e.g., engine response tracking).
