The OpSyn Model Server is a Python FastAPI application that generates complete workflow definitions from natural language prompts. It uses a fine-tuned Qwen2.5-Coder-7B model deployed on Modal (serverless GPU).

## Architecture

```
User Prompt → TypeScript Backend (/v1/opsyn/generate)
                    ↓
              Python FastAPI Server (Modal GPU)
                    ↓
              Fine-Tuned Qwen2.5-Coder-7B + LoRA
                    ↓
              Raw JSON Output
                    ↓
              Post-Processor v2 + Smart Matcher
                    ↓
              Valid FlowTemplate JSON
```

## Production Files

| File | Purpose |
|------|---------|
| `server_v2.py` | FastAPI server (deployed production server) |
| `modal_app_v2.py` | Modal cloud GPU deployment |

## Smart Matcher

The model sometimes generates names that are close but not exact. The Smart Matcher automatically fixes them using a 4-stage pipeline:

### Matching Stages

| Stage | Method | Example |
|-------|--------|---------|
| **1. Exact** | Direct comparison | `new_message` → `new_message` ✅ |
| **2. Normalized** | snake_case + prefix removal | `newMessage` → `new_message` ✅ |
| **3. Fuzzy** | rapidfuzz string similarity | `send_emial` → `send_email` ✅ |
| **4. Token** | Jaccard word overlap | `slack_send_message` → `send_message` ✅ |

### Name Normalization

Handles all naming conventions transparently:
- `sendEmail` → `send_email` (camelCase)
- `SendEmail` → `send_email` (PascalCase)
- `send-email` → `send_email` (kebab-case)
- `gmail_send_email` → `send_email` (piece prefix removal)

## Post-Processor

Takes raw model output and transforms it into valid, import-ready FlowTemplate:

### Processing Pipeline

1. **Extract JSON** — Strip markdown code blocks, text wrapping
2. **Fix piece names** — `slack` → `@activepieces/piece-slack`
3. **Fix versions** — Look up from `piece_registry.json`
4. **Smart-match names** — Fix trigger/action names
5. **Fix step naming** — Ensure `trigger`, `step_1`, `step_2` convention
6. **Fix step chaining** — Rebuild `nextAction` linked list
7. **Add required fields** — `valid`, `inputUiInfo`, etc.
8. **Set schema version** — `schemaVersion: "1"`
9. **Validate** — Check against FlowTemplate schema

## Modal Deployment

The model runs on Modal's serverless GPU infrastructure:

| Setting | Value |
|---------|-------|
| **GPU** | NVIDIA A10G (24GB VRAM) |
| **Memory** | 32 GB RAM |
| **Timeout** | 600 seconds |
| **Scale-down** | 20 seconds idle |
| **Concurrency** | 1 request at a time |
| **Volume** | `opsyn-model-cache` (persistent) |

### Deployment Commands

```bash
# First-time setup
modal volume create opsyn-model-cache

# Upload model weights
modal volume put opsyn-model-cache \
  ./qwen25_coder_7b_opsyn_lora_quality \
  /models/qwen25_coder_7b_opsyn_lora_quality

# Upload piece registry
modal volume put opsyn-model-cache \
  ./piece_registry.json /models/piece_registry.json

# Deploy to production
modal deploy modal_app_v2.py

# Test locally
modal serve modal_app_v2.py

# Verify volume contents
modal volume ls opsyn-model-cache /models
```

### Checking Deployment

```bash
# Run the check function
python -c "import modal; modal.App.lookup('opsyn-model-server-v2').check_model_files.remote()"
```

## Local Development

```bash
cd opsyn-model-server

# Install dependencies
pip install -r requirements.txt

# Start the server
python server_v2.py
# or
uvicorn server_v2:app --host 0.0.0.0 --port 8000 --reload
```

<Note>
  Running locally requires a CUDA-capable GPU with 16GB+ VRAM for model inference. CPU mode is supported but significantly slower.
</Note>
